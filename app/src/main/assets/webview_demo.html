常见坑位

下面这些能力都不在 WebView 本身,而是靠 WebChromeClient 回调,客户端没接好就会点了没反应

alert / confirm / prompt 分别走 onJsAlert / onJsConfirm / onJsPrompt。 基类设置了 webChromeClient 但没重写这三个方法,所以弹的是系统默认对话框。 自己接管时方法返回 true 却忘了调 result.confirm(),JS 会一直等,表现就是点了没反应; prompt 还常被老桥用来截 jsbridge:// 这类协议,无脑 return true 会把页面的 prompt 一起吞掉。

console.log 默认不进 Logcat。基类在 onConsoleMessage 里把它转成日志,过滤 BaseWebView 就能看到; 没有这个回调时,只能连 chrome://inspect 看页面控制台。
