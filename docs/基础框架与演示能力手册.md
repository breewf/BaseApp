### 1.2 一次页面的数据流

```
用户操作 / initData
        │
        ▼
ViewModel（BaseViewModel）
   ├─ 网络请求 launchRequest / launchRawRequest ──► Api（Retrofit suspend）
   ├─ 状态：pageState / isLoading（StateFlow，可重放）
   └─ 事件：uiEvent（SharedFlow，一次性，不重放）
        │
        ▼
基类页面（BaseActivity / BaseFragment）
   ├─ repeatOnLifecycle(STARTED) 收集三条流
   ├─ onUiEvent 分发到 onShowToast / onShowError / onNavigate / onGoBack / onCustomEvent
   ├─ showLoading(show) 驱动局部加载态
   └─ pageState → PageStateLayout.bind(state) 驱动整页状态层
        │
        ▼
页面子类只重写钩子 + 渲染业务数据
```

### 1.3 两条正交通道（必须区分）

| 通道 | 类型 | 语义 | 典型内容 |
| --- | --- | --- | --- |
| 状态 | `StateFlow` | 可重放，转屏后重新收集仍能拿到 | `isLoading`、`pageState`、业务数据 |
| 事件 | `SharedFlow`（`extraBufferCapacity=16`） | 错过不补，转屏不会重复弹 | `ShowToast`、`ShowError`、`Navigate`、`ShowResult` |

> 把 Toast 放进 StateFlow 会出现“转屏重复弹”；把状态放进 SharedFlow 会“错过就丢”。这是整个基类设计的核心约束。

## 2. 核心基类

### 2.1 BaseActivity

文件：[BaseActivity.kt](../app/src/main/java/com/hy/basic/BaseActivity.kt)

```kotlin
abstract class BaseActivity<VB : ViewBinding, VM : BaseViewModel> : AppCompatActivity()
```

| 能力 | API | 说明 |
| --- | --- | --- |
| 布局绑定 | `createBinding(inflater): VB` | 子类返回 `XxxBinding.inflate(inflater)` |
| 泛型反射 ViewModel | `createViewModel(): VM` | 默认解析第 2 个泛型；中间层转发泛型时重写 |
| 模板方法 | `initView → observeViewModel → initData` | `onCreate` 中固定顺序执行 |
| 统一 Toolbar | `showToolBar`、`toolbarTitle`、`showToolBarBack`、`onToolBarInitialized` | 壳布局 `abs_activity_toolbar.xml`，页面 XML 不再自带 Toolbar |
| 整页多状态 | `enablePageState`、`createPageStateConfig()` | 页面根 View 自动包进 `PageStateLayout`，状态层不遮 Toolbar |
| 一次性事件 | `onUiEvent(event)` | 默认按类型分发到各 `open` 钩子 |
| 错误钩子 | `onShowError(exception: ApiException)` | 默认长 Toast；401 等可重写跳登录 |
| 导航钩子 | `onNavigate(event: UiEvent.Navigate)` | 支持显式 Class / 任意 Intent / extras / flags |
| 返回钩子 | `onGoBack()` | 走 `onBackPressedDispatcher`，弹窗/折叠头拦截仍生效 |
| 加载态 | `showLoading(show: Boolean)` | 由 `isLoading` 引用计数驱动 |
| 状态重试 | `onPageRetry()` | 默认重新执行 `initData()` |
| 轻提示 | `showToast` / `showLongToast` | 统一走 `ToastKit` |
| 便捷启动 | `startActivity<A> { putExtra(...) }` | 泛型内联，少写 Intent |

关键实现细节：

- `showToolBar=false && enablePageState=false` 时直接 `setContentView(binding.root)`，不套壳。
- 只要 `showToolBar` 或 `enablePageState` 为 true，就使用壳布局：Toolbar + `flPageContent`。`enablePageState` 时内容再包一层 `PageStateLayout`。
- 壳布局在 `applyEdgeToEdgeInsets` 中处理 edge-to-edge：有 Toolbar 时把状态栏高度并入 Toolbar 高度并 `paddingTop`；无 Toolbar 时四边 inset 补在壳根上。
- 新增 `onConfigureInflater(inflater)` 钩子，在 `super.onCreate` 之前调用；目前唯一使用方是 `BaseSkinActivity`（`setFactory2` 只能装一次，晚一步会被 AppCompat 占掉）。
- 有 Toolbar 时背景为深色 `colorPrimary`，状态栏图标固定浅色（`isAppearanceLightStatusBars=false`）。
- `ShowResult` 分支不会调用私有的 `finishActivity`（那会再次 `setResult(null)` 清空回传数据），而是直接 `setResult + finish`。

### 2.2 BaseFragment

文件：[BaseFragment.kt](../app/src/main/java/com/hy/basic/BaseFragment.kt)

与 `BaseActivity` 同一套模板方法与事件钩子，差异点：

| 能力 | API | 说明 |
| --- | --- | --- |
| 布局绑定 | `createBinding(inflater, container): VB` | 返回 `XxxBinding.inflate(inflater, container, false)` |
| 防泄漏 | `_binding` 在 `onDestroyView` 置空 | `binding` getter 在 View 销毁后访问会抛明确异常 |
| 懒加载 | `isLazyLoad` | 首次 `resumed && !hidden` 才执行 `initData`，ViewPager 预加载页不会提前请求 |
| 整页多状态 | `enablePageState`、`createPageStateConfig()` | 状态层只覆盖 Fragment 自身内容，宿主 Toolbar/Tab 不受影响 |
| 事件收集 | `viewLifecycleOwner.lifecycleScope + repeatOnLifecycle(STARTED)` | 不会在 View 销毁后回调 UI |
| 宿主关闭 | `UiEvent.Finish` / `ShowResult` | 通过 `requireActivity()` 转发 `setResult + finish` |

懒加载触发点：`onViewCreated`（非懒加载直接执行）、`onResume`、`onHiddenChanged(false)`。数据只初始化一次（`isDataInit`）。

### 2.3 BaseViewModel

文件：[BaseViewModel.kt](../app/src/main/java/com/hy/basic/BaseViewModel.kt)

```kotlin
open class BaseViewModel : ViewModel() {
    val uiEvent: SharedFlow<UiEvent>          // 一次性事件
    val isLoading: StateFlow<Boolean>         // 引用计数加载态
    val pageState: StateFlow<PageState>       // 整页状态

    fun emitUiEvent(event: UiEvent): Boolean
    fun postApiException(exception: ApiException)
    fun startLoading()                        // 手动驱动非网络异步任务
    fun stopLoading()

    protected fun showPageLoading()
    protected fun showPageContent()
    protected fun showPageEmpty(message: CharSequence? = null)
    protected fun showPageNoNetwork(message: CharSequence? = null)
    protected fun showPageError(exception: ApiException)
    protected fun showPageError(message: CharSequence?, code: Int = 0)
}
```

- `isLoading` 用 `AtomicInteger` 计数：并发请求只有最后一个结束时才置 false。
- `uiEvent` 缓冲 16 条，`tryEmit` 不要求协程上下文；缓冲满时丢弃。
- `pageState` 默认 `PageState.Content`，未开启 `enablePageState` 的页面不会消费它。
- `showPageError(ApiException)` 通过 `PageState.from(exception)` 自动把网络类错误映射为 `NoNetwork`。

### 2.4 UiEvent 与钩子分发

文件：[UiEvent.kt](../app/src/main/java/com/hy/basic/page/UiEvent.kt)

| 事件 | 默认行为 | 可重写钩子 |
| --- | --- | --- |
| `ShowToast(message, long)` | Toast | `onShowToast` |
| `ShowError(exception)` | 长 Toast | `onShowError`（401 跳登录等） |
| `Navigate(target, flags, extras)` | 组装 Intent 启动 | `onNavigate` |
| `GoBack` | 返回分发器 | `onGoBack` |
| `Finish(resultCode, data)` | `setResult + finish` | 重写 `onUiEvent` 拦截 |
| `ShowResult(values, resultCode)` | 自动 `setResult + finish` | 与 `awaitResultBundle` 配套 |
| `Custom(tag, data)` | 默认提示未处理 | `onCustomEvent` |

`Navigate` 两个工厂：

```kotlin
UiEvent.Navigate.goto(LoginActivity::class.java) { putExtra("from", "profile") }
UiEvent.Navigate.by(Intent(Intent.ACTION_VIEW, uri))
```

`resultIntentOf` 支持 `CharSequence / Int / Long / Boolean / Float / Double`，其他类型统一 `toString()` 回传。

### 2.5 PageState 与 PageStateLayout

文件：[PageState.kt](../app/src/main/java/com/hy/basic/page/PageState.kt)、[PageStateLayout.kt](../app/src/main/java/com/hy/basic/page/PageStateLayout.kt)

```kotlin
sealed class PageState {
    data object Loading
    data object Content
    data class Empty(val message: CharSequence?)
    data class NoNetwork(val message: CharSequence?)
    data class Error(val message: CharSequence?, val code: Int)
}
```

- `PageState.from(exception)`：`CODE_NET_ERROR(4000)`、`CODE_TIMEOUT(4080)` → `NoNetwork`，其余 → `Error`。
- `PageStateLayout` 是一个 `FrameLayout`：`attachContent()` 把页面真实内容放最底层并预置 `Loading`，避免首帧闪烁。
- `bind(state, onRetry)`：同状态重复调用直接忽略；回到 `Content` 时状态层 180ms 淡出；切入其他状态直接不透明覆盖（不做淡入，避免透出底层内容）。
- 状态层布局约定 id（缺哪个就跳过，不崩溃）：
  `ivPageStateIcon` / `tvPageStateMessage` / `btnPageStateRetry`。
- `PageStateConfig` 可替换四个状态的 `xxxLayoutRes`，也可只改文案、颜色、图标、重试文案。
- `Loading` 状态没有“重试”语义，布局里的重试按钮会被隐藏。

### 2.6 LauncherSpec 与 ResultHostFragment

文件：[LauncherSpec.kt](../app/src/main/java/com/hy/basic/LauncherSpec.kt)

解决 `registerForActivityResult` 不能在 STARTED 之后注册的问题：无 UI 的 `ResultHostFragment` 在 `onAttach` 时按“谱键”注册 launcher，之后同一谱键复用。

| 谱 | 产出 |
| --- | --- |
| `StartActivity(intent)` | `ActivityResult`（resultCode + data） |
| `PickImage` / `GetContent(mime)` / `PickImages` / `PickVideo` | `Uri` / `List<Uri>` |
| `OpenDocument` / `CreateDocument(mime, name)` | `Uri` |
| `TakePicture(outputFile?)` | `Uri?`（自动经 FileProvider 落到缓存目录） |
| `ShareText(text)` | `ActivityResult` |
| `IntentSender(request)` | `ActivityResult` |
| `Custom(contract, input)` | contract 原生产出 |

对外一行 API：

```kotlin
val outcome = awaitResultBundle(intentOf(this, FormActivity::class.java)) // Pair<Int, Bundle?>?
val uri = awaitImagePicker()                                             // Uri?
val result = awaitResult(LauncherSpec.TakePicture()) as? Uri
val typed: MyResult? = awaitTypedResult(LauncherSpec.Custom(contract, input))
```

- Activity / Fragment 各有同名扩展；Fragment 版宿主挂在 `childFragmentManager`，互不串扰。
- `awaitResultBundle` 会把 `RESULT_CANCELED`（含目标页进程被杀）归一为 `null`。
- 宿主 `isStateSaved` 时返回 `null`，点击回调里可直接调用。
- 进程重建后恢复的宿主实例会丢失注入信息，`attachResultHost` 会移除换建。
- `TakePicture` 依赖 FileProvider：authority 为 `applicationId + ".fileprovider"`；部分 ROM 还需先申请 `CAMERA` 权限（否则 `SecurityException`）。

## 3. 网络层

### 3.1 Api：唯一入口

文件：[Api.kt](../app/src/main/java/com/hy/basic/network/Api.kt)

| API | 用途 |
| --- | --- |
| `Api.apiService` | 默认 `ApiService` 实例，进程内懒加载一次 |
| `Api.okHttpClient` | 全局共享连接池/线程池，多域名复用 |
| `Api.create<S>(baseUrl)` | 多域名创建接口实例，共用同一份 OkHttp |
| `Api.registerInterceptor(interceptor)` | 全局拦截器（Cookie、公共参数、缓存策略）；必须在首次请求前注册，否则直接抛 `IllegalStateException` |

- 自定义拦截器在前、日志拦截器最后，保证日志打印的是补全公共头之后的最终请求。
- 超时默认 10s（`NetConstants`），`retryOnConnectionFailure(true)`。
- `ApiService` 里现有接口是演示接口（apiopen），新增业务接口建议独立 Service + `Api.create`，或统一并入 `ApiService`。

### 3.2 响应信封与异常归一化

文件：[BaseHttpResponse.kt](../app/src/main/java/com/hy/basic/network/BaseHttpResponse.kt)、[ApiExceptionExt.kt](../app/src/main/java/com/hy/basic/network/ApiExceptionExt.kt)

```kotlin
class BaseHttpResponse<T> {
    var code: Int
    var msg: String?
    var message: String?
    var data: T?
    var statusCode: String?
    var desc: String?
    var result: T?
    var content: String?

    fun unwrap(): T? = data ?: result ?: content as? T
    fun throwApiException()   // 预留业务码校验钩子
}
```

- 历史接口字段不统一，`unwrap()` 按 `data → result → content` 优先级解包。
- 业务码校验统一入口是 `throwApiException()`：后端规范统一后在这里抛 `ApiException`，所有请求自动走统一异常通道。
- `ApiExceptionExt.toApiException` 把 `HttpException / UnknownHostException / SocketTimeoutException / JsonParseException / IOException` 归一为 `ApiException`。
- 错误码：`4999 未知`、`4998 空数据`、`4000 网络连接`、`4080 超时`、`4010 解析`、`5000 服务端`、`401 登录态失效`。

### 3.3 请求 API 矩阵

文件：[NetRequestExt.kt](../app/src/main/java/com/hy/basic/network/NetRequestExt.kt)

| 场景 | 信封接口（code/msg/data） | 裸 JSON 接口 |
| --- | --- | --- |
| 只关心成功数据（loading/异常全自动） | `launchRequest` | `launchRawRequest` |
| 串行依赖，需要判断上一步是否成功 | `awaitRequest`（失败返回 null） | `awaitRawRequest` |
| 需要自定义 Flow 操作符 | `request` | `requestRaw` |

```kotlin
// 1. 普通请求：成功回调只拿解包后的数据
launchRequest(block = { getTestResult() }) { data -> render(data) }

// 2. 串行：失败返回 null，异常已由全局通道提示
val city = awaitRawRequest { repository.searchCity(name) } ?: return@launch
val weather = awaitRawRequest { repository.forecast(city.lat, city.lon) } ?: return@launch

// 3. 需要操作符
request { getTestResult() }
    .map { ... }
    .catch { ... }
    .collect { ... }
```

执行策略：

- `flowOn(Dispatchers.IO)`：请求与解析在 IO 线程。
- `catch` 中 `CancellationException` 原样抛出，保持结构化并发。
- 其余异常统一 `toApiException` 后抛出。
- `launchFlow` 负责 `startLoading / stopLoading` 与 `postApiException`；`showLoading=false` 可用于静默请求。
- `await*` 失败返回 null 且异常已上报，调用方不要重复 Toast。

### 3.4 调用约定

- `launchRequest` 的 block 接收者已经是 `ApiService`，调用处直接写 `getTestResult()`，不要再写 `Api.apiService.xxx`。
- 空响应 / 空数据视为异常（`CODE_EMPTY_DATA`），由统一通道提示。
- 裸 JSON 接口的业务成功码（如油价 `status == 1`）必须由业务自己校验，网络层只负责“请求成不成”。
- `await` 返回 null 同时代表“请求失败”与“请求成功但数据为空”时，需要像天气 Demo 一样用 `launchRawRequest` 的布尔返回值区分。

## 4. 系统能力

### 4.1 权限

文件：[Permission.kt](../app/src/main/java/com/hy/basic/permission/Permission.kt)、[PermissionExt.kt](../app/src/main/java/com/hy/basic/permission/PermissionExt.kt)、[PermissionHostFragment.kt](../app/src/main/java/com/hy/basic/permission/PermissionHostFragment.kt)

**语义权限组（自动做版本归一）**

| 组 | 33+ | 33 以下 |
| --- | --- | --- |
| `Permission.CAMERA` | CAMERA | CAMERA |
| `Permission.MICROPHONE` | RECORD_AUDIO | RECORD_AUDIO |
| `Permission.CONTACTS` | READ_CONTACTS | READ_CONTACTS |
| `Permission.MEDIA` | READ_MEDIA_IMAGES | READ_EXTERNAL_STORAGE |
| `Permission.NOTIFICATION` | POST_NOTIFICATIONS | 空（无需申请） |
| `Permission.LOCATION` | FINE + COARSE | FINE |

**只读状态 `PermissionState`**

| 状态 | 含义 | UI 建议 |
| --- | --- | --- |
| `GRANTED` | 已授予 | 直接执行业务 |
| `DENIED` | 未授予，弹窗仍会出现 | 可先说明用途再申请 |
| `DENIED_FOREVER` | 不会再弹窗（勾选不再询问 / 11+ 二次拒绝） | 只能引导去设置 |
| `UNDECLARED` | Manifest 未声明 | 开发期配置错误，补 `uses-permission` |

`PermissionRecord` 用 SharedPreferences 记录“是否申请过 / 上次是否授予”，补齐系统 API 无法区分“还能弹”和“只能去设置”的盲区。

**申请与结果**

```kotlin
// 协程式（推荐）
val result = awaitPermissions(Permission.CAMERA)
when {
    result.allGranted -> openCamera()
    result.needsSettings -> Permission.openAppSettings(context)
    else -> toast("已拒绝，下次还能再问")
}

// 回调式
requestPermissions(Permission.MICROPHONE + Permission.NOTIFICATION) { result -> ... }

// 只读判断
if (context.hasPermission(Permission.CAMERA)) { ... }
val state = context.permissionState(Manifest.permission.CAMERA)
```

`PermissionResult` 三个集合互斥且覆盖全部申请项，派生属性：`allGranted`、`partiallyGranted`、`needsSettings`、`canAskAgain`、`allDenied`、`deniedAll`、`summary()`。未在 Manifest 声明的权限（`UNDECLARED`）会被归入 `deniedForever`，因此同样触发 `needsSettings`。

`PermissionHostFragment` 用 `Mutex` 串行化并发申请；已授予的权限不弹窗，申请前已授予的部分会补回结果；宿主状态已保存时直接按当前状态回填，不打扰用户。

### 4.2 本地持久化

文件：[MMKVStore.kt](../app/src/main/java/com/hy/basic/storage/MMKVStore.kt)、[SPStore.kt](../app/src/main/java/com/hy/basic/storage/SPStore.kt)

MMKV（推荐，App 启动时已 `MMKV.initialize(this)`）：

```kotlin
MMKVStore.putString("key", "value")
val name = MMKVStore.getString("key", "default")
MMKVStore.increase("launch_count")
MMKVStore.kv("business", multiProcess = true)   // 业务分库

// 属性委托：声明即读写
object Config {
    var nickname: String by MMKVStore.stringProp("nickname", "")
    var age: Int by MMKVStore.intProp("age", 18)
    var profile: DemoProfile by MMKVStore.jsonProp("profile", DemoProfile())
}

// 泛型集合
val list: List<User>? = MMKVStore.getObject("users", typeOf<List<User>>())
```

- 写入即时落盘，没有 `apply/commit` 概念；读取一律带默认值。
- `Parcelable` 走 MMKV 原生 Parcel 序列化，比 JSON 快，但改类字段要注意旧数据兼容。
- `jsonProp` 的 reified 版适合普通对象；带 `Type` 的重载当前签名面向 `Set<String>`，其他泛型结构用 `getObject(key, typeOf<...>())`。
- 多进程模式：同一 `mmapID` 的所有进程必须用相同模式，混用会触发 `checkProcessMode` 崩溃。

### 4.3 Room 数据库

文件：[BaseDao.kt](../app/src/main/java/com/hy/basic/db/BaseDao.kt)、[CommonConverters.kt](../app/src/main/java/com/hy/basic/db/CommonConverters.kt)、[RoomMigrations.kt](../app/src/main/java/com/hy/basic/db/RoomMigrations.kt)

```kotlin
@Dao
interface NoteDao : BaseDao<NoteEntity> {
    @Query("SELECT * FROM note ORDER BY createdAt DESC")

}
```

- `BaseDao<T>` 提供 suspend 的 `insert / insertList / update / updateList / delete`；查询按需自写。
- `CommonConverters`：`Date <-> epochMillis`、`List<String> <-> JSON`。
- 枚举需自定义转换器（Room 不内建），如 `PriorityConverter`。
- `RoomMigrations.sqlMigration(from, to, vararg sql)` 把 DDL 串成 `Migration`；每个跨版本都要给一条，缺中间版本 Room 会抛异常。

- DAO 返回 `Flow` 的 `@Query` 会在表数据变化后自动重新发射，UI 不需要手动刷新。

### 4.4 EventBus

文件：[EventBus.kt](../app/src/main/java/com/hy/basic/event/EventBus.kt)


可配置项：

| 属性 | 说明 |
| --- | --- |
| `loop` | 无限循环；数据不足 2 条自动退化 |
| `autoScroll` / `interval` | 自动轮播开关/间隔（最小 1000ms） |
| `scrollDuration` | 翻页动画时长，0 = 系统时长；默认 500ms |
| `pageMargin` / `setPageMarginDp(dp)` | 两侧露出相邻页（peek） |
| `imageScaleType` | 图片模式下的 ScaleType |
| `userScrollEnabled` | 是否允许手势滑动 |
| `transformer` | 内置动画，赋值会清掉自定义动画 |
| `indicatorStyle` | `DOTS / DOTS_SLIDER / BAR / TEXT`，null 关闭 |
| `indicatorGravity` / `indicatorMargin` | 指示器位置/边距 |
| `onPageClick` / `onPageSelected` / `onPageScrolled` / `onPageScrollStateChanged` | 回调（下标均为真实下标） |
| `realItemCount` / `currentItem` | 真实条数 / 当前真实页 |
| `pager` / `indicator` | 逃生门：底层 ViewPager2 / 指示器 View |

方法：`select(position, smooth)`、`next()`、`prev()`、`start()`、`stop()`、`setCustomTransformer { page, position -> }`、`addPageCallback { position, offset, dragging -> }`。

内部约定：

1. 循环靠“虚拟下标”：页数 = 数据量 × 100，初始落中间；对外统一折算真实下标。
2. 自动轮播自管起停：只在 `autoScroll && 已挂载 && 可见 && 未滑动 && 数据 > 1 && 有下一页` 时排队；页面切走/隐藏自动暂停。
3. 露边实现：每页内容左右内缩 + 每帧按 position 向中心靠拢，不改页宽，snap 与手势不受影响。
4. 指示器 `selection` 允许越出端点一格，循环首尾用环形插值/擦除过渡。
5. 18 种内置动画：`NONE / FADE / DEPTH / ZOOM / ZOOM_SLIDE / ACCORDION / CUBE / CUBE_IN / FLIP / FLIP_VERTICAL / ROTATE_UP / ROTATE_DOWN / FORE_TO_BACK / BACK_TO_FORE / TABLET / ZOOM_IN / SCALE_IN_OUT / FLOW`；每帧前置复位，换动画不残留脏状态。

XML 属性：`banner_loop`、`banner_autoScroll`、`banner_interval`、`banner_scrollDuration`、`banner_pageMargin`、`banner_transformer`、`banner_userScrollEnabled`、`banner_scaleType`、`banner_indicator`、`banner_indicatorGravity`、`banner_indicatorMargin`、`banner_indicatorColor`、`banner_indicatorSelectedColor`。

- 与拖拽互斥：拖拽期间页面置 `dragInProgress=true`；侧滑展开/跟手时 `isDragLocked()` 为 true，长按拖拽应被 `isLocked` 拦掉。
- 列表滚动、数据变化、行回收都会自动收起/归零。

### 5.10 WebView 与 JS Bridge

文件：[BaseWebViewActivity.kt](../app/src/main/java/com/hy/basic/web/BaseWebViewActivity.kt)、[WebJsBridge.kt](../app/src/main/java/com/hy/basic/web/WebJsBridge.kt)、[WebViewExt.kt](../app/src/main/java/com/hy/basic/web/WebViewExt.kt)

**BaseWebViewActivity**：壳布局固定为“进度条 + WebView 容器 + 错误页”，子类一般只配地址与白名单。

```kotlin
class AgreementActivity : BaseWebViewActivity<AgreementViewModel>() {
    override val initialUrl = "https://m.xxx.com/agreement"
    override val allowedHosts = setOf("m.xxx.com")
    override val jsBridgeEnabled = true

    override fun onWebViewReady(savedInstanceState: Bundle?) {
        bridge?.on("close") { _, result -> result.success(); finish() }
    }
}
```

| 可配置/可重写 | 说明 |
| --- | --- |
| `initialUrl` | 首屏地址 |
| `allowedHosts` | 站内白名单；空集合时所有 http(s) 都在 WebView 内打开 |
| `sslTolerantHosts` | 允许忽略证书错误的域名（一般只给内网/调试） |
| `jsBridgeEnabled` / `jsBridgeName` | 是否创建 Bridge / JS 访问名（默认 `NativeBridge`） |
| `useWebTitle` | 是否用网页 title 覆盖 Toolbar 标题 |
| `onWebViewReady` / `onWebPageFinished` / `onWebTitleChanged` | 生命周期回调 |
| `configureWebSettings(settings)` | 补 UA、缓存策略等 |
| `handleWebBack()` | 返回键处理，默认有历史就后退 |
| `isBridgeTrusted(url)` | Bridge 信任判断：`file://` 或 `allowedHosts` 放行 |
| `loadUrl / reloadWeb / showWebError` | 加载/重载/错误页 |

内置行为：

- 返回键先尝试网页后退，没有历史才交给系统。
- `shouldOverrideUrlLoading` 分流：http(s) 白名单内留在 WebView，外部打开；`file/about/data/javascript/blob` 交给 WebView；`tel/mailto/intent://` 交给系统（`intent://` 用 `Intent.parseUri`）。
- `onReceivedError` 只处理主 frame，忽略 `ERROR_UNKNOWN`；SSL 默认拦截，白名单域名放行。
- `onRenderProcessGone` 销毁旧 WebView 并重建，Bridge 与 client 重新挂载。
- 支持 `<input file>` 文件选择（取消也会回传 null，避免下次点击无反应）。
- `onSaveInstanceState` 保存前进/后退栈；转屏优先恢复历史。
- edge-to-edge 下键盘弹起自行补 IME 底部 inset。

**WebJsBridge**：页面调原生、原生回结果或推事件。

```javascript
// JS 侧（页面加载完成后自动注入 helper）
WebBridge.call("toast", { text: "hi" }).then(...).catch(...)
WebBridge.on("nativePush", data => ...)

// 不注入 helper 时的手写协议
NativeBridge.post(action, paramsJson, callbackId)
window.__webBridgeResult(callbackId, ok, data)
window.__webBridgeEvent(event, data)
```

```kotlin
bridge.on("toast") { params, result ->
    toast(params.optString("text"))
    result.success()
}
bridge.emit("nativePush", "来自原生")
bridge.release()
```

- `@JavascriptInterface` 不能漏；回调线程是 JavaBridge，内部已切主线程。
- 同一 `callbackId` 只回一次；JS helper 有 10s 超时兜底。
- 页面未加载完时 `emit` 会缓存，加载完成后补发（最多 20 条）。
- 信任判断只看顶层 URL；iframe 也能调用 Bridge，所以白名单是唯一防线。

### 5.12 换肤（日夜间 / 多形态）

文件：[SkinManager.kt](../app/src/main/java/com/hy/basic/skin/SkinManager.kt)、[BaseSkinActivity.kt](../app/src/main/java/com/hy/basic/skin/BaseSkinActivity.kt)、[SkinInflater.kt](../app/src/main/java/com/hy/basic/skin/SkinInflater.kt)、[NightSkinSource.kt](../app/src/main/java/com/hy/basic/skin/NightSkinSource.kt)、[SkinExt.kt](../app/src/main/java/com/hy/basic/skin/SkinExt.kt)

完整的设计与 API 说明见 [换肤框架技术说明](换肤框架技术说明.md)，本节只保留接入要点。

日夜间使用同一套资源名：浅色值在 `values/`，深色值在 `values-night/`。`NightSkinSource` 通过 `createConfigurationContext` 生成两套强制指定 `uiMode` 的 `Resources`，取色不依赖当前 Activity 的 Resources；`SkinManager` 在切换时遍历已注册页面的 View 树，按每个 View 上的属性槽位重新取值。页面与布局都不重建。

#### 接入

颜色资源：

```xml
<!-- values/colors.xml -->
<color name="skin_bg_page">#FFF8F8F8</color>

<!-- values-night/colors.xml 同名覆盖 -->
<color name="skin_bg_page">#FF121212</color>
```

Activity 继承 `BaseSkinActivity`，布局中的颜色按资源名引用：

```kotlin
class SettingsActivity : BaseSkinActivity<ActivitySettingsBinding, SettingsViewModel>() {
    override fun createBinding(inflater: LayoutInflater) = ActivitySettingsBinding.inflate(inflater)
}
```

Fragment、RecyclerView 与普通控件沿用原有基类。Fragment 的布局由宿主 Activity 的 inflater 解析，槽位照常记录。

切换入口：

```kotlin
SkinManager.switchTo(SkinMode.DARK)            // 深色
SkinManager.switchTo(SkinMode.LIGHT)           // 浅色
SkinManager.switchTo(SkinMode.FOLLOW_SYSTEM)   // 跟随系统
SkinManager.toggle()                           // 深浅互切
```

模式写入 MMKV，冷启动时由 `SkinManager.initialize` 读取。

#### 常用 API

| API | 说明 |
| --- | --- |
| `SkinManager.switchTo(mode)` / `toggle()` | 切换模式，`FOLLOW_SYSTEM / LIGHT / DARK` |
| `SkinManager.isDarkFlow` | 当前深浅状态；代码绘制的内容订阅后重绘 |
| `SkinManager.color / colorStateList / drawable` | 按当前皮肤取资源 |
| `setBackgroundSkin` / `setTextColorSkin` 等 | 代码切换形态，资源 id 写回槽位 |
| `SkinManager.setEngine(COMPAT)` | 改用 `AppCompatDelegate` + recreate |
| `SkinManager.setEnabled(false)` | 关闭框架，下一次创建页面时生效 |
| `SkinManager.ignore(view)` | 该 View 不再自动刷新 |
| `SkinManager.setPack(pack)` / `registerPack(pack)` | 切换 / 注册节日皮肤包，`setPack(null)` 回默认皮肤 |
| `SkinManager.setSource(source)` | 替换默认来源，节日包会重新叠上去 |

#### 资源缺失时的取值

`values-night` 是限定符覆盖，不要求每个资源都有对应版本。系统从候选资源中取最匹配的一份：

| 定义位置 | 深色下的取值 |
| --- | --- |
| 仅 `values` | `values` 的值，不抛异常，也不会变成透明 |
| 仅 `values-night` | night 的值（唯一候选），不抛异常 |
| 两处都没有 | 槽位跳过，控件保持原值；`SkinManager.color` 返回 0 |
| 仅 `drawable-night` | 浅色下同样取 night 图 |

`values-night/colors.xml` 中的 `skin_*` 与 `values` 一一对应。演示页的「缺夜间配置」卡片（`skin_demo_day_only`）覆盖了仅 `values` / 仅 `drawable` 的取值路径。

#### 属性支持范围

| 分组 | XML 属性 |
| --- | --- |
| 文字 | `textColor`、`textColorHint`、`textColorLink` |
| 背景 | `background`、`foreground`、`backgroundTint`（android / app 命名空间） |
| 图片 | `src`、`tint` |
| 复合图 | `drawableStart`、`drawableTop`、`drawableEnd`、`drawableBottom` |
| 进度条 | `progressTint`、`progressBackgroundTint`、`secondaryProgressTint`、`indeterminateTint` |
| 滑块 | `thumbTint`、`tickMarkTint` |
| 按钮 | `buttonTint` |
| 列表 | `LinearLayout` 的 `divider` |
| 卡片 | `cardBackgroundColor` |

表外的属性（`elevation`、`strokeColor`、自定义控件内部颜色等）通过 `IDarkMode` 或 `setSkinRes` 处理。

#### 节日皮肤

节日包只声明与默认皮肤不同的资源，其余继续走默认皮肤。`SkinPack` 持有颜色和 drawable 两张映射表：

```kotlin
val SPRING = SkinPack(
    id = "spring",
    label = "春节",
    colors = mapOf(
        R.color.skin_accent to R.color.skin_festival_accent,
        R.color.skin_bg_page to R.color.skin_festival_page,
    ),
    drawables = mapOf(
        R.drawable.skin_btn_pressable to R.drawable.skin_festival_btn_pressable,
    ),
)

SkinManager.registerPack(SPRING)   // App 启动时注册，持久化过会自动恢复
SkinManager.setPack(SPRING)        // 切换
SkinManager.setPack(null)          // 回默认
```

`FestivalSkinSource` 包在默认来源外，`color / colorStateList / drawable` 先查映射再回落到默认来源。节日资源自身仍可带 `values-night`、`drawable-night` 变体，明暗切换不受影响。

drawable 内部引用的颜色不经过映射：`skin_mood_liked` 这类资源引用了 `skin_accent`，节日包需要同时映射该 drawable（演示里的 `skin_festival_mood_liked`）。节日包依赖自研刷新，`COMPAT` 引擎下只处理日夜。

演示：`fragment_skin_color.xml` 的「节日皮肤」卡片，春节包覆盖 `skin_accent`、`skin_bg_page`、`skin_btn_pressable`、`skin_mood_liked`；选择结果写入 MMKV。

#### 多形态

XML 中写默认形态，代码判断后切换到 B/C 时，原生 setter 不更新槽位，切肤会回到 XML 的值。扩展函数在改属性的同时把资源 id 写回槽位：

```kotlin
view.setBackgroundSkin(R.drawable.skin_mood_liked)         // 背景（Drawable 或颜色资源）
view.setBackgroundColorSkin(R.color.skin_bg_card)
view.setTextColorSkin(R.color.skin_accent)                 // TextView 文字/提示/链接色
view.setImageResourceSkin(R.drawable.skin_btn_pressable)   // ImageView
view.setCardBackgroundColorSkin(R.color.skin_bg_card)
view.setProgressTintListSkin(R.color.skin_accent)          // 进度条/滑块/按钮着色
view.setCompoundDrawableStartSkin(R.drawable.skin_btn_pressable)
```

参数为资源 id；`Color.RED`、现成的 Drawable 没有对应的 id，无法记录。形态保存在 View 上，View 重建后（列表复用、转屏、COMPAT 引擎 recreate）新 View 没有该槽位，按 XML 默认值处理。

#### 自绘、Drawable 与引擎

- 自绘 View 实现 `IDarkMode.onSkinChanged(isDark)`，在回调里重新取色并 `invalidate()`。
- 只换颜色时，一张 drawable 内部引用 `skin_*` 即可；形状、圆角或图片本身有变化时，在 `drawable-night/` 放同名文件。取到的 Drawable 统一 `mutate()`。
- `SELF` 运行时刷新；`COMPAT` 使用 `AppCompatDelegate` + recreate。两者共用同一套 `values-night` 资源。

#### 基类职责

`BaseSkinActivity` 在 `onConfigureInflater` 中安装 Factory2（早于 `super.onCreate`）；在 `onCreate` 注册 `window.decorView`，`onDestroy` 反注册；为 RecyclerView 添加子 View 监听；窗口底色与系统栏图标跟随皮肤。Toolbar 页的基类跳过系统栏处理，需要换肤的 Toolbar 页重写 `applySystemBarStyle()`，并通过 `ignore(toolbar)` 自行维护背景、标题和返回箭头（参考 `SkinFragmentDemoActivity`）。

#### 常见现象

| 现象 | 原因 |
| --- | --- |
| 某个控件颜色不变 | 颜色写在 `style` / `theme` 中；Factory2 只读取布局里直接写出的属性 |
| 代码设过色，切肤后回到 XML 的值 | 原生 `setTextColor` / `setBackground` 不更新槽位 |
| 整个页面不变 | Activity 未继承 `BaseSkinActivity` |
| 页面根布局背景不变 | 根 View 为 `ScrollView` 时该槽位不刷新，页面背景通常放在内层容器 |
| Toolbar 不变 | 壳布局的 Toolbar 不在自动刷新范围内，由页面维护 |
| 弹框、悬浮窗不变 | 独立 Window，不在 `decorView` 遍历范围 |
| 列表新条目颜色不对 | 形态保存在 View 上，复用出的新 View 没有该槽位 |

## 10. 关键注意事项清单

### 10.1 基类与生命周期

1. `registerForActivityResult` 不能懒注册：权限/结果回传统一走 `PermissionHostFragment` / `ResultHostFragment`，不要在点击回调里临时 `registerForActivityResult`。
2. Fragment 的 `binding` 只在 `onCreateView ~ onDestroyView` 可用；异步回调一律用 `viewLifecycleOwner`。
3. `isLazyLoad` 依赖 `BEHAVIOR_RESUME_ONLY_CURRENT_FRAGMENT`；用旧版 FragmentPagerAdapter 时注意设置。
4. 中间层二次转发泛型（如 `BaseWebViewActivity<VM>` 把 VM 放第 1 个参数）必须重写 `createViewModel()`，否则基类反射会回退 `BaseViewModel`。
5. 转屏去重用 `StateFlow.value == null` 判断，不要在 `initData` 里无条件重复请求。
6. `UiEvent` 是事件不是状态：Toast/导航/回传走事件，业务数据走 StateFlow。
7. `ShowResult` 不要自己再 `setResult(null)`，基类分支已处理“回传数据不被清空”。

### 10.2 网络

1. 拦截器必须在首次请求前注册；`registerInterceptor` 在 OkHttpClient 初始化后会抛异常。
2. Retrofit `baseUrl` 必须以 `/` 结尾，方法路径写相对路径。
3. `launchRequest` 的 block 接收者已是 `ApiService`，不要写 `Api.apiService.xxx`。
4. `await*` 失败返回 null 且异常已上报，不要重复提示；需要区分“失败/空数据”时用 `launch*` 的布尔返回值。
5. 裸 JSON 接口的业务码由业务校验；`BaseHttpResponse.throwApiException()` 是未来统一业务码的预留口。
6. 协程取消必须原样抛出，封装的 `catch` 已处理，不要吞 `CancellationException`。

### 10.3 存储与数据库

1. MMKV 使用前必须 `MMKV.initialize(this)`（App 已做）。
2. 同一 `mmapID` 多进程模式必须一致，混用崩溃。
3. Room 升版本必须同步 `@Database.version` 与每条 `Migration`；`version=` 用字面量，不要前向引用伴生常量。
4. 业务主表不要用破坏性迁移；缓存表才考虑 `fallbackToDestructiveMigration`。
5. DAO 的 Flow 查询在表变化后自动重发，UI 不要额外手动刷新。

### 10.4 弹窗

1. `BaseDialogFragment` / `BaseBottomSheetDialogFragment` 必须靠 `getTheme()` 给弹框主题；只定义 `themeRes` 不接线无效，会出现白底闪烁、宽度铺不满、蒙层/动画失效。
2. 窗口动画必须在窗口加入 WindowManager 之前设置（`onCreateDialog`），放 `onStart` 只对退场有效。
3. 卡片皮肤窗口不是悬浮窗口；`widthRatio=1f` 直接 `MATCH_PARENT`，不要用 `displayMetrics.widthPixels` 换算（横屏/刘海/分屏会留缝）。
4. BottomSheet behavior 顺序：`setHideable` 会重置状态，必须在 `setState` 前；`setShouldRemoveExpandedCorners` 也必须在 `setState` 前，否则圆角已经动画掉了。
5. 面板根 View 必须是 `NestedScrollView` / `RecyclerView`，否则拖拽与滚动不联动。
6. `LENGTH_INDEFINITE` 的 Snackbar 必须给 action，否则用户无法关闭。
7. Toast 是“最新优先”，连续弹只看到最后一条；覆盖式更新先 `ToastKit.cancel()`。

### 10.5 列表与手势

1. BRVAH4 非 Diff 模式 `move` 直接改 `items`，`submitList` 的集合必须可变。
2. BRVAH4 没有 `MultiItemEntity`，多类型用 `BaseMultiItemAdapter` + `onItemViewType` + `addItemType`。
3. 网格/瀑布流嵌在 ScrollView 里必须 `disableInnerScroll()`，item 高度需全量铺开。
4. Tab 页内列表与 ViewPager2 冲突用 `resolvePagerConflict()`；横向列表/侧滑/网格四向拖拽必须 `blockPagerOnDown=true`。
5. 侧滑与拖拽同用：拖拽先挂（手势检测在前），侧滑展开时 `isDragLocked()` 要拦掉长按拖拽；侧滑接管后 ItemTouchHelper 收不到 UP，必须靠 `dragInProgress` 让路。
6. 侧滑删除后 `position` 可能已变，撤销要按 id 找回位置再插入。
7. 瀑布流不支持 ItemTouchHelper 拖拽（跨列换位会乱）。

### 10.6 图片、富文本与转场

1. Glide 圆角必须 `CenterCrop` + `RoundedCorners` 组合；`Path.addRoundRect` 的 radii 必须 8 个 float。
2. 颜色必须写满 8 位 ARGB，缺 alpha 会透明。
3. `SpannableStringBuilder.append(Spanned)` 在 Android 12 以下不拷贝 span，混排统一用 `appendSpanned`。
4. 含 `ClickableSpan` 的 TextView 必须 `enableLinkTouch()`。
5. 共享元素返回用 `finishAfterTransition()`；列表 item 每次 bind 都要重设唯一 `transitionName`。
6. `sharedElementsUseOverlay=false`，否则图片转场先动画一张空快照。

### 10.7 WebView

1. `@JavascriptInterface` 不能漏，漏了 JS 侧是 `undefined` 且不报错。
2. 页面未加载完 `emit` 会缓存，`onPageStarted` 会清空上一页未发事件。
3. 信任判断只能看顶层 URL；iframe 也能调用 Bridge，白名单是唯一防线。
4. `onReceivedError` 只处理主 frame，忽略 `ERROR_UNKNOWN`（跳转取消）。
5. 渲染进程崩溃必须销毁旧 WebView 再重建，旧实例不能复用。
6. 销毁前先 `removeJavascriptInterface`，否则可能泄漏；`destroySafely` 会先从视图树移除。
7. edge-to-edge 下键盘弹起要自己补 IME inset，`adjustResize` 不再缩窗口。

### 10.8 换肤

1. `setFactory2` 只允许设置一次，Factory2 必须在 `super.onCreate` 之前装（`BaseActivity.onConfigureInflater`），否则报 `A factory has already been set on this LayoutInflater`。
2. 取色统一走 `SkinManager.color/colorStateList/drawable`；非重建页面的 `context.resources` 可能仍是系统配置。只写 `values` 的资源在深色下取 `values` 的值；只写 `values-night` 的资源在浅色下取 night 的值，两种情况都不会抛异常。
3. 只有布局里直写的引用能接到，style/theme 里的颜色接不到；这类控件用 `IDarkMode` 或 `setSkinRes`。
4. 原生 `setTextColor(int)` / `setBackground(Drawable)` 会被切肤打回 XML 值；`setSkinRes` 系列会把资源 id 写回槽位，形态得以保留。
5. 页面背景位于内层容器时刷新正常；`ScrollView` 根 View 的 background 槽位在 Fragment + ViewPager2 下不刷新。
6. `values-night` 一旦存在，未接入换肤的页面在系统深色下也会跟着变色；语义色统一 `skin_` 前缀后，影响范围限于这些资源。
7. 官方引擎（COMPAT）下自研刷新链路整体停用，靠 recreate；`setEngine` 切回自研时会把 AppCompat 夜间模式复位到跟随系统。节日包同样只在 SELF 下刷新。
8. DialogFragment / PopupWindow 是独立 Window，不在 `decorView` 遍历范围内，需要单独注册或自行处理。
9. 基类壳布局的 Toolbar 背景写死在 `abs_activity_toolbar.xml`；`ignore(toolbar)` 后由页面维护背景，否则会被槽位刷回固定底色。
10. 资源缺失（shrink、名字写错）时槽位跳过，控件保持原值；`SkinManager.color` 返回 0。
