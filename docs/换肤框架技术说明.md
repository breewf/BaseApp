## 1. 概述

换肤框架在页面不重建的前提下切换日夜间与节日皮肤。

资源名保持不变：浅色值写在 `values/`，深色值写在 `values-night/`。切肤时用另一套 `Resources` 解析同一个资源 id，再刷新已注册页面的 View 树。布局与页面实例都不重建。

| 组成 | 文件 | 职责 |
| --- | --- | --- |
| 资源来源 | `SkinSource`、`NightSkinSource`、`FestivalSkinSource`、`SkinPack` | 按当前皮肤解析颜色与 drawable |
| 属性槽位 | `SkinInflater`、`SkinPart`、`SkinSlot` | inflate 时记录控件上可换的属性 |
| 入口与刷新 | `SkinManager`、`BaseSkinActivity` | 切换模式/节日包、遍历刷新、系统栏与窗口底色 |
| 配置 | `SkinConfig`、`SkinMode` | 总开关、引擎、明暗模式 |

## 2. 设计

### 2.1 资源组织

```
res/
├── values/colors.xml           skin_bg_page = #FFF8F8F8
├── values-night/colors.xml     skin_bg_page = #FF121212
├── drawable/skin_btn.xml       内部引用 skin_* 颜色
└── drawable-night/skin_btn.xml 形状或图片需要变化时才提供
```

日夜差异由资源限定符承担，Java/Kotlin 代码里不出现 `_night` 后缀，也不需要用 `getIdentifier` 拼资源名。

### 2.2 属性槽位

`SkinInflater` 包装 `LayoutInflater.Factory2`，在 View 创建后读取 `AttributeSet`，把布局里直接写出的资源引用记成槽位：

```kotlin
internal class SkinSlot(
    var resId: Int,      // 资源 id,代码切形态时更新
    val kind: SkinPart,  // 处理方式
)
```

- 槽位列表保存在 `View.setTag(R.id.skin_slot_tag, ...)` 上，每个 View 一份。
- 只识别布局内联属性；`style`、`theme` 里的颜色不进入槽位。
- 解析按控件类型分流，例如 `TextView` 解析 `textColor`，`ImageView` 解析 `src`，`ProgressBar` 解析 `progressTint`。
- 完整属性表见[第 5 节](#5-属性支持范围)。

### 2.3 资源来源

`SkinSource` 是取资源的统一接口：

```kotlin
interface SkinSource {
    val isDark: Boolean
    fun applyMode(isDark: Boolean)
    fun invalidate()
    fun color(@ColorRes id: Int): Int
    fun colorStateList(@ColorRes id: Int): ColorStateList?
    fun drawable(@DrawableRes id: Int): Drawable?
}
```

**NightSkinSource**（默认实现）

- 用 `createConfigurationContext` 生成浅色、深色两套 `Resources`，`uiMode` 强制指定，其余配置跟随应用。
- 两套 `Resources` 懒加载，配置变化时通过 `invalidate()` 丢弃缓存。
- 取资源失败时回落到应用默认配置；仍失败则 `color` 返回 0，`colorStateList`/`drawable` 返回 null。

**FestivalSkinSource**（节日包）

- 构造参数为默认来源 + `SkinPack`。
- `color/colorStateList/drawable` 先查节日包映射，未映射的 id 原样交给默认来源。
- `isDark/applyMode/invalidate` 全部委托给默认来源，明暗逻辑不受节日包影响。

**自定义来源**

`SkinManager.setSource(source)` 替换默认来源；当前节日包会重新叠在新来源上。

### 2.4 刷新链路

```
switchTo / setPack / setSource / refresh
            │
            ▼
   currentSource.applyMode / 替换来源
            │
            ▼
   refreshAllNow()
            │
            ▼
   遍历 roots(decorView)
            │
            ├─ 按槽位重新取色/取图
            ├─ IDarkMode.onSkinChanged(isDark)
            ├─ RecyclerView 子 View attach 监听
            └─ 递归子 View
```

页面创建阶段的路径：

```
BaseSkinActivity.onConfigureInflater
  └─ SkinManager.install(inflater)
       └─ SkinInflater.install        Factory2 只在此处安装
BaseSkinActivity.onCreate
  └─ SkinManager.register(decorView)  立即套一遍
BaseSkinActivity.onDestroy
  └─ SkinManager.unregister(decorView)
```

`SkinManager.attach()` 在 View 创建时记录槽位，自研引擎下立即套色；`register()` 再遍历一次，用于补上 `IDarkMode` 回调与 RecyclerView 监听。

### 2.5 引擎

| 引擎 | 行为 |
| --- | --- |
| `SkinEngine.SELF` | 遍历 View 树就地换肤，不重建页面；支持节日包 |
| `SkinEngine.COMPAT` | `AppCompatDelegate.setDefaultNightMode` + recreate；只处理日夜 |

- 两种引擎下 Factory2 都会记录槽位，切回 `SELF` 后可以直接刷新。
- `COMPAT` 下 `applyTo` 直接返回，节日包不生效。
- 进入 `COMPAT` 时写入 `skin.compat` 标记；`SkinManager.initialize` 检测到残留标记会把 AppCompat 复位为跟随系统。
- 运行时切换引擎走 `SkinManager.setEngine()`；直接改 `SkinConfig.engine` 不会触发刷新。

## 3. 接入

### 3.1 资源

```xml
<!-- values/colors.xml -->
<color name="skin_bg_page">#FFF8F8F8</color>

<!-- values-night/colors.xml 同名覆盖 -->
<color name="skin_bg_page">#FF121212</color>
```

颜色统一写 8 位 ARGB。形状、圆角或图片本身需要变化时，再提供 `drawable-night/` 同名文件；只换颜色时一张 drawable 内部引用 `skin_*` 即可。

### 3.2 页面

```kotlin
class SettingsActivity : BaseSkinActivity<ActivitySettingsBinding, SettingsViewModel>() {
    override fun createBinding(inflater: LayoutInflater) =
        ActivitySettingsBinding.inflate(inflater)
}
```

布局中的可换属性直接引用资源名：

```xml
<TextView
    android:background="@color/skin_bg_page"
    android:textColor="@color/skin_text_primary" />
```

Fragment、RecyclerView 与普通控件沿用原有基类。Fragment 的布局由宿主 Activity 的 inflater 解析，槽位照常记录。DialogFragment、PopupWindow 是独立 Window，不在 `decorView` 遍历范围内。

`BaseSkinActivity` 的默认行为：

- 窗口底色取 `R.color.skin_bg_page`，根布局透明时不会露出旧色；取不到值或框架关闭时保留主题底色；
- 无 Toolbar 时状态栏、导航栏图标跟随 `isDark`；
- 无 Toolbar 且未开启整页状态时，补偿系统栏与刘海 inset；
- 有 Toolbar 的页面由子类重写 `applySystemBarStyle()`；Toolbar 背景与标题通过 `ignore(toolbar)` 后由页面维护。

### 3.3 切换

```kotlin
SkinManager.switchTo(SkinMode.DARK)            // 深色
SkinManager.switchTo(SkinMode.LIGHT)           // 浅色
SkinManager.switchTo(SkinMode.FOLLOW_SYSTEM)   // 跟随系统
SkinManager.toggle()                           // 深浅互切
```

模式写入 MMKV（`skin.mode`），冷启动时由 `SkinManager.initialize` 读取。

`Application.onCreate` 中的初始化：

```kotlin
MMKV.initialize(this)
SkinManager.initialize(this)
SkinManager.registerPack(FestivalPacks.SPRING)
```

## 4. API

### 4.1 SkinManager

| API | 说明 |
| --- | --- |
| `initialize(context)` | 读模式、创建默认来源、处理官方引擎残留 |
| `install(inflater)` | 安装 Factory2，`BaseSkinActivity` 在 `super.onCreate` 之前调用 |
| `switchTo(mode)` / `toggle()` | 切换明暗模式，模式写入 MMKV |
| `isDarkFlow` | 当前深浅状态；自绘内容订阅后重绘 |
| `isDark` / `mode` | 当前深浅 / 当前模式 |
| `color(id)` / `colorStateList(id)` / `drawable(id)` | 按当前皮肤取资源 |
| `setPack(pack)` | 切换节日包，`null` 回默认；写入 MMKV |
| `registerPack(pack)` | 注册节日包；冷启动后首次注册时按持久化记录恢复 |
| `pack` | 当前节日包，供 UI 回显 |
| `packFlow` | 当前节日包状态，订阅后随切换刷新 |
| `setSource(source)` | 替换默认来源，节日包重新叠上去 |
| `setEngine(engine)` | 切换自研 / 官方引擎 |
| `setEnabled(enabled)` | 总开关，下一次创建页面时生效 |
| `setSkinRes(view, part, resId)` | 代码切形态，资源 id 写回槽位并立即生效 |
| `ignore(view)` | 该 View 退出自动刷新 |
| `refresh()` | 手动刷新已注册页面 |
| `register(root)` / `unregister(root)` | 页面根 View 注册 / 反注册 |

### 4.2 SkinMode 与 SkinConfig

| 项 | 取值 | 说明 |
| --- | --- | --- |
| `SkinMode` | `FOLLOW_SYSTEM` / `LIGHT` / `DARK` | `label` 为中文名 |
| `SkinConfig.enabled` | Boolean | false 时不再安装 Factory2、不刷新页面 |
| `SkinConfig.engine` | `SELF` / `COMPAT` | 运行时切换走 `setEngine` |

### 4.3 扩展函数（`SkinExt.kt`）

命名规则为“原生方法 + Skin”，参数为资源 id：

| 原生 | 换肤版 |
| --- | --- |
| `setBackground` | `setBackgroundSkin(drawableRes)` |
| `setBackgroundColor` | `setBackgroundColorSkin(colorRes)` |
| `setForeground` | `setForegroundSkin(drawableRes)` |
| `setBackgroundTintList` | `setBackgroundTintListSkin(colorRes)` |
| `setTextColor` | `setTextColorSkin(colorRes)` |
| `setHintTextColor` | `setHintTextColorSkin(colorRes)` |
| `setLinkTextColor` | `setLinkTextColorSkin(colorRes)` |
| `setImageResource` | `setImageResourceSkin(drawableRes)` |
| `setImageTintList` | `setImageTintListSkin(colorRes)` |
| 复合图 | `setCompoundDrawableStartSkin` / `Top` / `End` / `Bottom` |
| `setProgressTintList` | `setProgressTintListSkin(colorRes)` |
| `setProgressBackgroundTintList` | `setProgressBackgroundTintListSkin(colorRes)` |
| `setSecondaryProgressTintList` | `setSecondaryProgressTintListSkin(colorRes)` |
| `setIndeterminateTintList` | `setIndeterminateTintListSkin(colorRes)` |

### 4.4 IDarkMode

```kotlin
class SkinRingView @JvmOverloads constructor(...) : View(...), IDarkMode {
    override fun onSkinChanged(isDark: Boolean) {
        ringColor = SkinManager.color(R.color.skin_accent)
        invalidate()
    }
}
```

Canvas、Paint、Shader 里的颜色不经过属性槽位，由该回调重新取色。

## 5. 属性支持范围

| 分组 | XML 属性 | 适用控件 |
| --- | --- | --- |
| 文字 | `textColor`、`textColorHint`、`textColorLink` | `TextView` 及其子类 |
| 背景 | `background`、`foreground`、`backgroundTint` | 所有 View |
| 图片 | `src`、`tint` | `ImageView` |
| 复合图 | `drawableStart`、`drawableTop`、`drawableEnd`、`drawableBottom` | `TextView` |
| 进度 | `progressTint`、`progressBackgroundTint`、`secondaryProgressTint`、`indeterminateTint` | `ProgressBar` |
| 滑块 | `thumbTint`、`tickMarkTint` | `SeekBar` |
| 按钮 | `buttonTint` | `CompoundButton` |
| 分割线 | `divider` | `LinearLayout` |
| 卡片 | `cardBackgroundColor` | `CardView` |

`android` 与 `app` 两个命名空间都会读取，`backgroundTint`、`tint`、`buttonTint` 两类写法都支持。

表外的属性（`elevation`、`strokeColor`、自定义控件内部颜色等）通过 `IDarkMode` 或 `setSkinRes` 处理。

## 6. 多形态控件

XML 写默认形态，代码按业务状态切到其他形态时，原生 setter 不更新槽位，切肤会回到 XML 的值。扩展函数在修改属性的同时把资源 id 写回槽位：

```kotlin
private fun renderMood() {
    val bgRes: Int
    val textColorRes: Int
    val label: String
    when (mood) {
        Mood.NORMAL -> {
            bgRes = R.drawable.skin_mood_normal
            textColorRes = R.color.skin_text_primary
            label = "正常态"
        }
        Mood.LIKED -> {
            bgRes = R.drawable.skin_mood_liked
            textColorRes = R.color.skin_accent
            label = "已喜欢"
        }
        Mood.DISLIKED -> {
            bgRes = R.drawable.skin_mood_disliked
            textColorRes = R.color.skin_danger
            label = "不喜欢"
        }
    }
    binding.tvMood.setBackgroundSkin(bgRes)
    binding.tvMood.setTextColorSkin(textColorRes)
    binding.tvMood.text = label
}
```

参数为资源 id；`Color.RED`、现成的 Drawable 没有对应的 id，无法记录。

形态保存在 View 上。View 重建后（列表复用、转屏、`COMPAT` 引擎 recreate），新 View 没有该槽位，按 XML 默认值处理，在绑定阶段重新调用一次即可。

## 7. 节日皮肤

节日包只声明与默认皮肤不同的资源：

```kotlin
val SPRING = SkinPack(
    id = "spring",
    label = "春节",
    colors = mapOf(
        R.color.skin_accent to R.color.skin_festival_accent,
        R.color.skin_bg_page to R.color.skin_festival_page,
    ),
    drawables = mapOf(
        R.drawable.skin_btn_pressable to R.drawable.skin_festival_btn_pressable,
    ),
)
```

注册与切换：

```kotlin
SkinManager.registerPack(SPRING)   // App 启动时注册，持久化过会自动恢复
SkinManager.setPack(SPRING)        // 切换到春节
SkinManager.setPack(null)          // 回默认皮肤
```

规则：

- 映射表里没有的资源继续使用默认皮肤，未适配的页面不受影响。
- 节日资源本身可以带 `values-night`、`drawable-night` 变体，明暗切换与节日包相互独立。
- 节日包 id 写入 MMKV（`skin.pack`），`registerPack` 在冷启动后首次注册时按记录恢复。
- drawable 内部引用的颜色不经过映射。例如 `skin_mood_liked` 内部用了 `skin_accent`，需要把该 drawable 一并映射到节日版本。
- 节日包依赖自研刷新，`COMPAT` 引擎下只处理日夜。

## 8. 资源缺失与降级

`values-night` 是限定符覆盖，不要求每个资源都有对应版本。系统从候选资源中取最匹配的一份：

| 定义位置 | 深色下的取值 |
| --- | --- |
| 仅 `values` | `values` 的值，不抛异常，也不会变成透明 |
| 仅 `values-night` | night 的值（唯一候选），不抛异常 |
| 两处都没有 | 槽位跳过，控件保持原值；`SkinManager.color` 返回 0 |
| 仅 `drawable-night` | 浅色下同样取 night 图 |

`SkinManager.color` 在来源取不到值时回落到应用默认配置，仍取不到才返回 0。`colorStateList`、`drawable` 在未初始化或取不到时返回 null，槽位直接跳过。

基类窗口底色取 `skin_bg_page`；`SkinConfig.enabled=false` 或取不到值时保留主题底色，不设置透明背景。

## 9. 限制与常见现象

| 现象 | 原因 |
| --- | --- |
| 某个控件颜色不变 | 颜色写在 `style` / `theme` 中，Factory2 只读取布局内联属性 |
| 代码设过色，切肤后回到 XML 的值 | 原生 `setTextColor` / `setBackground` 不更新槽位 |
| 整个页面不变 | Activity 未继承 `BaseSkinActivity` |
| 页面根布局背景不变 | `ScrollView` 根 View 的 background 槽位在 Fragment + ViewPager2 下不刷新，页面背景通常放在内层容器 |
| Toolbar 不变 | 壳布局的 Toolbar 不在自动刷新范围内，由页面维护 |
| 弹框、悬浮窗不变 | 独立 Window，不在 `decorView` 遍历范围 |
| 列表新条目颜色不对 | 形态保存在 View 上，复用出的新 View 没有该槽位 |
| 切到同一模式没有反应 | `switchTo` 对相同模式直接返回；需要时调用 `refresh()` |
| 运行时关闭换肤后仍保留当前配色 | `setEnabled(false)` 停止后续刷新，不还原已经套用的颜色；下一次创建页面时不接管 |

其他约束：

- `setFactory2` 只能设置一次，Factory2 必须在 `super.onCreate` 之前安装。
- `setEnabled(false)` 在页面创建阶段生效；运行中切换只影响后续刷新。
- `ignore(view)` 清空槽位，之后调用 `setSkinRes` 会重新接管该 View。
- 自绘 View 的 `onSkinChanged` 由 `applyTo` 触发，`setSkinRes` 不会触发该回调。
